# Как разместить «Порядок»

## Публичное демо с гостевым режимом — Render Free (бесплатно)

Ссылку можно дать любому человеку: он нажимает **«Попробовать без регистрации»** и получает свою отдельную временную базу. Работает всё, включая синхронизацию с Яндекс Контактами.

1. Зайдите на [render.com](https://render.com) через GitHub (карта для бесплатного плана не нужна) и дайте Render доступ к репозиторию `poryadok-crm`.
2. **New → Blueprint**, выберите репозиторий. Render прочитает `render.yaml` и создаст бесплатный Node-сервис `poryadok-crm`. Паролей вводить не нужно.
3. Дождитесь сборки (около 3–5 минут). Адрес вида `https://poryadok-crm.onrender.com` — это и есть ссылка для людей. Каждый пуш в `main` пересобирает сайт.

Как устроен гостевой режим (`CRM_GUEST_MODE=1`):

- у каждого гостя своя база в памяти сервера: на диск она не пишется, другие гости её не видят;
- база удаляется по кнопке **«Выйти и удалить»**, через `CRM_GUEST_HOURS` часов (по умолчанию 6) и при любом перезапуске сервера;
- одновременно не больше `CRM_MAX_GUESTS` гостей (в `render.yaml` — 20), с одного IP — не больше 10 гостевых входов в час;
- пароль приложения Яндекса гостя хранится только в памяти сервера до выхода или 2 часа. Он проходит через ваш сервер — предупредите об этом человека и попросите удалить пароль приложения в Яндекс ID после теста.

Особенности бесплатного плана Render:

- после ~15 минут без запросов сервис засыпает, первое открытие занимает 30–60 секунд, а все гостевые базы при этом стираются;
- сервер находится за пределами России — если Яндекс начнёт отклонять подключения, переезжайте на российский VPS через Docker (раздел «Свой сервер» ниже, добавьте `CRM_GUEST_MODE=1`).

Если в настройках сервиса задать `CRM_OWNER_PASSWORD` (от 12 символов), на странице входа рядом с гостевой кнопкой появится обычный вход по логину. Но без постоянного диска данные этого аккаунта тоже стираются при перезапуске.

## Постоянные аккаунты для двух пользователей (платный план)

У каждого логина своя база клиентов, заказов, оплат, шаблонов и статусов. API выбирает базу по серверной сессии. Чужие записи не отображаются. Очистка и Яндекс относятся только к текущему аккаунту. Два входа задаются при размещении; регистрации через сайт пока нет.

## GitHub + Render

1. Распакуйте `poryadok-crm.zip`. Создайте приватный репозиторий GitHub и загрузите содержимое архива в корень: рядом должны лежать `package.json`, `render.yaml`, `server/`, `src/`. Загрузите также скрытую папку `.openai/` — она нужна скрипту сборки. Персональных баз и настоящих паролей в архиве нет.
2. `render.yaml` в репозитории описывает бесплатное гостевое демо. Для постоянных аккаунтов создайте Web Service вручную (параметры ниже) на платном плане с постоянным диском `/var/data`; проверьте текущую стоимость перед подтверждением.
3. Задайте разные `CRM_OWNER_PASSWORD` и `CRM_COLLEAGUE_PASSWORD`, каждый от 12 символов. По умолчанию логины `owner` и `colleague`; их можно поменять через `CRM_OWNER_LOGIN` и `CRM_COLLEAGUE_LOGIN`. Эти названия не дают доступа к чужой базе: права на собственные данные одинаковые. Реальные пароли вводите только в настройках хостинга.
4. Дождитесь сборки. Откройте выданный HTTPS-адрес и войдите своим логином. Второму человеку передайте адрес и его отдельные реквизиты входа.
5. Для собственного домена задайте `PUBLIC_ORIGIN=https://ваш-домен` без пути. Иначе используется `RENDER_EXTERNAL_URL`. Входить нужно по настроенному адресу. Изменение переменных перезапускает сервер и требует повторного входа.

При ручном создании Web Service: runtime **Node**, версия **24**, build `npm ci && npm run build`, start `npm start`, health check `/healthz`, один экземпляр. Добавьте диск `/var/data`, `CRM_DB_PATH=/var/data/crm.sqlite`, логины и пароли из `.env.example`. Базы создаются отдельными файлами `crm-<хеш логина>.sqlite` внутри этой папки. Переименование логина создаст пустой аккаунт; смена пароля при прежнем логине сохраняет данные.

Инструкция сверена с документацией Render: [Node-сервис](https://render.com/docs/deploy-node-express-app), [Blueprint](https://render.com/docs/blueprint-spec), [постоянные диски](https://render.com/docs/disks), [адрес сервиса](https://render.com/docs/environment-variables). Размещение и сборка контейнера на хостинге ещё не выполнялись.

## Перенос текущих данных

В локальной CRM: **Настройки → Скачать базу JSON**. На размещённом сайте войдите под своим логином: **Настройки → Перенести базу из файла**, выберите JSON и подтвердите перенос. Импорт доступен в пустую базу. Второй пользователь начинает с пустой базы. Локальные данные сами в интернет не отправляются. JSON содержит личные данные — не загружайте его в GitHub.

## Данные и Яндекс

База сохраняется на выбранном сервере, в SQLite на постоянном диске. В размещённом режиме база не записывается в localStorage. Это разграничение доступа между пользователями приложения; администратор сервера и хостинг технически имеют доступ к серверному хранилищу. Приложение не шифрует SQLite дополнительным собственным ключом.

Каждый отдельно подключает Яндекс паролем приложения «Контакты». Пароль находится только в памяти серверного процесса: после перезапуска или истечения двухчасовой сессии нужно подключение заново. Передача идёт через HTTPS вашего сайта к серверу и затем к CardDAV Яндекса. Синхронизация требует предпросмотра и применения. Живой аккаунт Яндекса ещё не проверен; автоматические проверки используют тестовый транспорт.

**Очистить данные** с подтверждением стирает базу текущего аккаунта и отключает его сессии Яндекса. Чужие базы и контакты на самом Яндексе сохраняются. Скачанные JSON и резервные снимки провайдера кнопка не удаляет; условия хранения снимков проверяйте у провайдера.

## Свой сервер

Dockerfile использует Node 24. Соберите `docker build -t poryadok-crm .`. Заполните `.env` по `.env.example`, задайте `CRM_DB_PATH=/data/crm.sqlite` и настоящий HTTPS `PUBLIC_ORIGIN`. Запуск: `docker run -d --name poryadok --restart unless-stopped --env-file .env -p 127.0.0.1:3000:3000 -v poryadok-data:/data poryadok-crm`. Нужен HTTPS reverse proxy с сохранением публичного Host. Запускайте один экземпляр. Файл `.env` не включайте в репозиторий.

Для локальной проверки: Node 24, `npm ci`, `npm run build`, затем `node --env-file=.env server/start.mjs`; используйте локальный `PUBLIC_ORIGIN=http://127.0.0.1:3000` и доступный путь `CRM_DB_PATH`.

Выкладка только `dist/client` на статический хостинг не даст входа, серверного хранения и интеграции Яндекса.
